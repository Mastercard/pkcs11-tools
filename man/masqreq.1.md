% MASQREQ(1) | pkcs11-tools

# NAME

masqreq - adapt a PKCS#10 CSR subject and extensions without re-signing

# SYNOPSIS

**masqreq**
**-c** *csrfile*
**-d** *subjectdn*
\[**-r**]
\[**-o** *outfile*]
\[**-e** *sanfield* ...]
\[**-X**]
\[**-v**]
\[**-h**]
\[**-V**]

# DESCRIPTION

**masqreq** (masquerade request) takes an existing PKCS#10 Certificate Signing
Request (CSR) from a file, replaces its Subject DN and optionally its Subject
Alternative Name extensions, and writes the modified CSR to an output file or
standard output. The public key is taken from the original CSR.

Because **masqreq** does not have access to the corresponding private key, it
does **not** re-sign the request. The signature in the output CSR is therefore
always invalid. This is intentional: the tool is meant for scenarios where a
CSR generated by an appliance has a rigid DN structure that must be transformed
before submission to a CA, and the CA accepts unsigned or structurally modified
requests.

No PKCS#11 library or token connection is required: **masqreq** operates
entirely on local files and does not require authentication.

# OPTIONS

**-c** *csrfile*
:   Path to the input PKCS#10 request file (PEM or DER). Mandatory. The
    public key from this file is preserved in the output CSR.

**-d** *subjectdn*
:   Subject Distinguished Name in strict OpenSSL format, e.g.
    `/CN=mysite.net/O=My Org/C=BE`. Mandatory. By default the components are
    listed in human order (leftmost attribute becomes innermost RDN) and
    **masqreq** reverses them to the binary DER order required by X.509. Use
    **-r** to supply the DN already in binary order.

**-r**
:   Interpret the Subject DN (**-d**) in reverse (binary DER) order.

**-o** *outfile*
:   Write the modified CSR to *outfile* instead of standard output.

**-e** *sanfield*
:   Subject Alternative Name extension field. May be repeated. Accepted
    prefixes:

    `DNS:`*hostname* — DNS name.

    `email:`*address* — RFC 822 e-mail address.

    `IP:`*address* — IPv4 address.

**-X**
:   Add a Subject Key Identifier X.509v3 extension. The value is the SHA-1
    hash of the public key modulus (or equivalent for non-RSA keys).

**-v**
:   Verbose output: print the decoded content of the generated CSR to
    standard output after writing it.

**-h**
:   Print usage information and exit.

**-V**
:   Print version information and exit.

# ENVIRONMENT

**masqreq** does not use any PKCS#11 environment variables; it operates
entirely on local files.

# EXIT STATUS

**0**
:   Success.

Any non-zero value indicates an error; see **pkcs11-tools**(7) for the meaning
of the exit codes.

# EXAMPLES

Replace the Subject DN in an existing CSR:

    masqreq -c original.csr -d '/CN=another CN'

Replace the Subject DN and add SAN fields, writing to a new file:

    masqreq -c appliance.csr \
        -d '/CN=server.example.com/O=Example Corp/C=US' \
        -e DNS:server.example.com \
        -e DNS:www.example.com \
        -o modified.csr

Add a Subject Key Identifier extension to the modified request:

    masqreq -c input.csr \
        -d '/CN=test.example.com/C=BE' \
        -X \
        -o output.csr

Inspect the result verbosely:

    masqreq -c input.csr -d '/CN=test/C=BE' -v
